# AWR2944P ROS 2 driver — quick start

Community driver for **TI AWR2944PEVM / AWR2944P**, tested with Ubuntu 24.04 and ROS 2 Jazzy. Supports UART TLVs, the TI DDM_ENET TCP stream, and synthetic replay. This is not an official TI ROS driver.

The default Ethernet profile targets **SDK 4.7.2.1 DDM_ENET, 10 Hz**. UART reception was tested with SDK 4.6.2.1; the public UART profile has since been corrected to the AWR2944P antenna layout and has not been revalidated on hardware. Per-board calibration and long-duration USB-LAN stability are unverified.

## Build

Install ROS 2 Jazzy and rosdep first, then:

```bash
git clone https://github.com/SangwooJung98/awr2944p_ros2_driver.git
cd awr2944p_ros2_driver
source /opt/ros/jazzy/setup.bash
rosdep update
rosdep install --from-paths ros2_ws/src --ignore-src -r -y --rosdistro jazzy
cd ros2_ws
colcon build --symlink-install --packages-select awr2944_driver
source install/setup.bash
export ROS_DOMAIN_ID=0 ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
```

Source the ROS and workspace setup files and use the same ROS domain in every terminal.

## Try without hardware

```bash
ros2 launch awr2944_driver replay.launch.py
```

This displays **synthetic**, not measured, point clouds at 10 Hz in RViz.

## Ethernet

Connect the board's specified 12 V supply to J12, J8 USB to the PC for CLI control, and J9 Ethernet to a dedicated PC NIC. Normal boot: S1 at XDS, J20 fitted, J18/J17 open. Install the matching AWR2x44P DDM_ENET firmware separately from TI.

Configure only the sensor-facing NIC to `192.168.1.10/24`, with no default route. The radar at `192.168.1.200` connects to the PC's TCP server on port 7. The [main guide](../README.md) includes NetworkManager and serial-permission commands. Identify your actual CLI port; `/dev/ttyACM0` is only the default.

Reset the board, then run from the repository root:

```bash
export ROS_DOMAIN_ID=0 ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
bash tools/run_ethernet.sh cli_port:=/dev/ttyACM0 \
  auto_start:=true max_run_seconds:=0.0 connect_timeout:=20.0
```

The systemd helper grants `CAP_NET_BIND_SERVICE` only to this user-owned process. In another sourced terminal:

```bash
rviz2 -d "$(ros2 pkg prefix --share awr2944_driver)/rviz/radar.rviz"
```

Stop measurement:

```bash
ros2 service call /radar/stop std_srvs/srv/Trigger '{}'
```

Check diagnostics for confirmed stop. **Reset the board before the next Ethernet start**, because the stock firmware does not reconnect after a session closes:

```bash
ros2 service call /radar/start std_srvs/srv/Trigger '{}'
```

The default run limit is 60 s; `max_run_seconds:=0.0` disables it. Exit the driver with Ctrl+C or `sudo systemctl stop awr2944-ethernet`. Do not start duplicate driver services.

## UART

With matching **UART DDM firmware** on the board:

```bash
ros2 launch awr2944_driver usb.launch.py cli_port:=/dev/ttyACM0 \
  data_port:=/dev/ttyACM1 auto_start:=true max_run_seconds:=0.0
```

Switching the stock Ethernet application to UART output requires a compatible firmware application; `enetStreamCfg 0` does not switch the output transport.

## Data and configuration

`/radar/points` uses SensorDataQoS and float32 fields `x,y,z,velocity,snr,noise,intensity,range`. Default frame: `radar_link`. TI coordinates become ROS coordinates as `(y, -x, z)`: X forward, Y left, Z up. The default TF is identity for standalone visualization; supply measured mounting extrinsics on a robot.

Ethernet has no SNR, noise, temperature, sensor timestamp or sensor frame ID. Missing floating-point fields are NaN. Timestamps and Ethernet sequence numbers are generated by the host. RViz uses `velocity` coloring and Decay Time 0.

Edit the default cfg, stop measurement, reset, and start again. A different `config_file:=/absolute/path/custom.cfg` requires restarting the driver. Keep board-specific antenna geometry and DDM phase order correct. See [configuration](configuration.md), [firmware](firmware.md), [troubleshooting](troubleshooting.md), and [validation](validation.md).
