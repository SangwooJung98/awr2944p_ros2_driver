# 검증 기록과 한계

2026-10-22 기준입니다. 이 문서는 Humble 포팅 검증과 기반 Jazzy 버전의 기존 기록을 구분합니다.

## Humble 포팅

- Ubuntu 24.04 호스트에 Docker Engine을 설치하고 공식 `ros:humble-ros-base-jammy`로 Ubuntu 22.04 / ROS 2 Humble 이미지를 빌드했습니다.
- 이미지 안에서 `rosdep install`, `rosdep check`, colcon 빌드가 통과했습니다. cfg·launch·RViz·합성 데이터가 이미지에 포함됩니다.
- 로컬 자동 테스트와 Humble 실제 센서 수신 검증은 진행 중입니다. 아래의 기존 실측 수치는 Jazzy에서 얻은 결과입니다.
- GitHub Actions는 Humble 컨테이너의 symlink 설치·일반 설치 테스트와 별도 Docker 이미지 빌드·실행 검사를 수행합니다.

## 기반 Jazzy 버전의 실제 보드 기록 (2026-10-21)

- AWR2944PEVM / AWR2944P에서 UART DDM과 SDK 4.7.2.1 DDM_ENET 포인트 수신 및 RViz 표시를 확인했습니다.
- AWR2944P 안테나 배열·DDM 순서로 수정한 Ethernet cfg에서 340프레임, 약 10.0000 Hz, 18,219포인트를 수신한 구간이 있습니다. 해당 구간의 파싱 오류·발행 큐 누락·빈 포인트 프레임은 0이었습니다.
- 이전 안테나 설정에서 수집한 약 314초의 TCP 기록에서는 완성 프레임 3,140개, TCP 순번 공백 0, 빈 프레임 0이었습니다. 그 중 ROS 600프레임은 원본과 변환 결과가 일치했습니다. 이 결과는 전송·파싱 검증이며 안테나 모델의 정확도를 검증한 결과가 아닙니다.
- 과거 USB 수신 검증에는 이전 안테나 cfg가 사용됐습니다. 공개 USB cfg는 AWR2944P 배열로 수정했으나 이 수정본의 UART 실측은 수행하지 않았습니다.

개별 보드의 거리·위상 보정, 장착 자세/TF, 기준 표적을 이용한 각도·거리 오차, 고온·장시간 안정성은 검증하지 않았습니다. 서로 다른 시점의 포인트 수를 USB/Ethernet 전송 방식의 성능 차이로 해석하지 않습니다.

## 기반 Jazzy 버전의 자동 테스트 (2026-10-21)

자동 테스트는 합성 UART 데이터, CSV 기대값, PTY CLI 에뮬레이터, localhost TCP와 실제 ROS 2 메시지·서비스를 사용합니다. 보드가 연결되지 않아도 실행됩니다.

공개본은 Ubuntu 24.04 / ROS 2 Jazzy에서 빌드한 후 **43개 테스트 통과, 실패·오류·건너뜀 0개**를 확인했습니다.

검증 항목은 패킷 분할·결합, 손상·비정상 길이·NaN·0포인트, Ethernet 프레이밍, ROS 축·필드·타임스탬프, 시작·정지·재시작 순서, 무수신 정지, 반복 SIGINT 종료, AWR2944P 안테나 설정입니다. Humble 브랜치에서도 같은 테스트를 실행합니다.

합성 데이터는 `tools/generate_sample.py`에서 재현할 수 있습니다. 자동 테스트의 통과는 RF 하드웨어 성능이나 물리적 측정 정확도를 입증하지 않습니다.

## 기반 Jazzy 버전의 설치 재현 점검 (2026-10-21)

- 공개 GitHub 저장소를 별도 디렉터리에 새로 clone하고 기존 ROS 워크스페이스 환경과 사용자 Python 패키지를 제외한 상태에서 빌드했습니다. 43개 테스트가 통과했습니다.
- 실제 `rosdep` 검사에서 해석되지 않는 `ament_python` 의존성 선언을 발견해 `python3-setuptools`로 수정했습니다. `ament_python`은 패키지의 빌드 타입으로 유지합니다. `ros2 launch`의 실행 의존성도 명시했으며 수정 후 `rosdep check`가 통과했습니다.
- cfg 2개, launch 3개, RViz 설정, 합성 데이터 등 설치 리소스를 확인하고 실제 launch에서 합성 PointCloud2 20프레임·600포인트를 약 10 Hz로 수신했습니다.
- 일반 복사 설치 후 소스와 빌드 디렉터리를 기존 경로에서 치운 상태에서도 같은 재생 검사를 통과했습니다. 실행 시 원본 개발 디렉터리를 참조하지 않습니다.
- `tools/check_install.py`와 GitHub Actions에서 설치 리소스·launch·PointCloud2 재생 검사를 반복할 수 있습니다. RViz와 TF 실행 파일의 존재도 확인하며, 이 자동 검사는 RViz 창을 띄우지 않습니다.

이 점검은 소프트웨어 설치 재현성 검사입니다. 다른 물리 PC의 시리얼 권한·NIC·방화벽·그래픽 환경과 실제 보드 측정까지 대신 검증하지는 않습니다. TI 펌웨어는 보드에 별도로 준비해야 합니다.
